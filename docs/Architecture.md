# Архитектура графика

График состоит из шести основных компонентов. `ChartController` выполняет роль
ViewModel внутри компонента: предоставляет свойства для привязок, реализует
`INotifyPropertyChanged` и содержит команды через существующий `RelayCommand`.
События `MainWindowViewModel` и привязки панели инструментов остаются прежними.

| Компонент | Ответственность |
| --- | --- |
| `ChartView` | WPF-события, размер, фокус, курсор, захват мыши, popup, измерение времени отрисовки |
| `ChartController` | Команды, взаимодействие, обновление состояния и индикаторов, координация хранения фигур |
| `ChartState` | Данные, камера, панели, настройки и состояние взаимодействия одного графика |
| `ChartRenderer` | Рисование подготовленного `ChartRenderFrame` через `DrawingContext` |
| `ChartTransform` | Неизменяемые коэффициенты и преобразования Chart/World/View и индикаторной панели |
| `AxisLayout` | Неизменяемые деления шкал, подписи и минимальный отображаемый шаг цены |

## Владение состоянием и обновления

`ChartView` создаёт свой Controller и Renderer. Контроллер владеет State;
`ChartInteractionState` внутри State хранит выбор, создание, перетаскивание и
перекрестие. Статических режимов взаимодействия в `TechnicalAnalysisTool` нет.
Свойства State доступны наружу для чтения, коллекции имеют представления только
для чтения. `ChartView.GetIndicators()` возвращает копию списка для совместимости.

При изменении камеры или геометрии Controller вычисляет viewport, пересоздаёт
Transform и AxisLayout, уведомляет свойства и команды, вызывает `ViewportChanged`
и `RenderRequested`. Инициализация камеры происходит при наличии данных и
ненулевых размеров, до отрисовки. Новый State содержит пустую серию;
демонстрационные данные загружает приложение.

`DataMinPrice` и `DataMaxPrice` описывают диапазон данных с существующим отступом
10% и не изменяют видимую область. Live-обновление запрашивает только отрисовку.
Закрытие свечи и расширение истории пересчитывают данные и RSI, сохраняя камеру.

## Команды и ввод

Controller предоставляет команды вписывания данных, сброса шкал, привязки последней
свечи справа, начала создания, отмены и удаления фигуры. `CanExecute` учитывает
готовность данных и выбор. Методы `HandlePointerDown`, `HandlePointerMove`,
`HandlePointerUp`, `HandleContextMenu` и `HandleKey` возвращают `InteractionResult`.
View применяет его курсор, фокус, захват мыши и действие popup.

Команды передают эффекты через `ViewActionRequested`. Изменения состояния всегда
происходят независимо от наличия подписчика. Потеря захвата завершает drag;
выгрузка View и смена символа также сбрасывают создание и выбор. View отписывается
при выгрузке и подписывается снова при загрузке.

`ShowCandleOutlines` остаётся DependencyProperty View и синхронизируется со
свойством Controller через `SetCurrentValue`, сохраняя существующую привязку.

## Кадр и индикаторы

`PrepareRenderFrame()` получает ровно один `CandleSeriesSnapshot` каждой отображаемой серии. Renderer,
ценовые метки и резервное вычисление времени свечей используют этот снимок.
История свечей не копируется в массив на каждом кадре; копируются только небольшие
коллекции ссылок на фигуры, индикаторы и точки незавершённой фигуры.

Renderer не зависит от Controller или View и не изменяет камеру, выбор или режим
создания. Допускаются прежние локальные кэши геометрии фигур при рисовании.

Сравнение хранится в `ChartState`: вторичная серия, символ, общая видимая свеча
нормализации и режим автоматического вписывания. `AxisLayout` строит процентные
деления относительно этой свечи. Контроллер пересчитывает нормализацию при навигации
и обновлении любой серии; ручное вертикальное перемещение или масштабирование
отключает автоматическое вписывание до сброса шкалы. Удаление сравнения восстанавливает
исходную вертикальную камеру, сохраняя текущую область времени. Событие
`VisibleTimeRangeChanged` запрашивает историю независимой вторичной подписки.

Линейка находится в `ChartInteractionState` каждого графика. Контроллер обрабатывает
два клика, движение указателя и отмену; измерение не сохраняется как фигура.
После второго клика работают шкалы и панель индикаторов, а следующий клик на основном
графике убирает измерение. Escape, смена инструмента, серии или символа очищают Линейку.
Кадр хранит значения её точек и один снимок вторичной серии, поэтому Renderer рисует
оба дополнения без обращений к изменяемому состоянию или дополнительных снимков.

Индикаторы получают `IndicatorDrawContext` с кадром и Transform. RSI рассчитывается
из снимка и функции получения времени, без зависимости от Controller.

Сетка и шкалы используют одни и те же деления AxisLayout. Начальный масштаб цены:
`abs(last.close) × 0.20` (±10%). При достижении ограничений zoom используется
фактически применённый коэффициент, чтобы точка под курсором не смещалась.

## Потоки и хранение

Загрузка, конвертация, демоданные и кэш начальных свечей используют массивы
`ccxt.OHLCV[]`; отдельной структуры свечи приложения нет. `OHLCV` в исходниках —
глобальный псевдоним `ccxt.OHLCV`. Конвертер проверяет входные данные и сохраняет
прежнее правило: отсутствующие числовые цены и объём заменяются нулями,
отсутствующая временная метка отклоняется. Метод расширения `GetDateTime()`
работает непосредственно с типом CCXT. Таймфрейм передаётся отдельно в запросе и при установке данных графика
через `SetCandles(candles, timeframe)` или `SetSeries(series, timeframe)`.
Время начала и конца определяется по самим свечам. Общая история продолжает
храниться в блоках `CandleSeries`, а отрисовка получает `CandleSeriesSnapshot`.

Методы изменения состояния вызываются в UI-контексте. Обработчик смены символа в
окне выполняет переход в Dispatcher при необходимости. Controller сериализует
смены символа через `SemaphoreSlim`; менеджер после файловых `await` возвращается
в вызывающий контекст перед изменением коллекции. JSON и текущие точки сохранения
сохраняются. Стили popup изменяет через `ApplyToolStyle` с проверкой принадлежности
фигуры этому графику. Пока смена символа ожидает сохранения/загрузки, создание и
редактирование фигур отключены: новая фигура не должна попасть в очищаемую коллекцию.

## Проверки

`ChartArchitectureTests` проверяет геометрию до рисования, пределы zoom, обновления
данных, команды, жесты, независимость графиков, привязки, жизненный цикл View,
сериализацию смен символа и WPF-отрисовку. Чтобы экспортировать PNG, перед запуском
теста рисования задайте `BOTVIEW_CHART_PREVIEW` абсолютным путём к выходному файлу.

После сборки тесты запускаются через `BotView.Tests.exe` с фильтром `-class`.
Стандартный VSTest-режим `dotnet test` несовместим с текущей конфигурацией
Microsoft.Testing.Platform на .NET 10. Стартовая загрузка рынков и основной серии
восстановлена при переносе сравнения: поиск вторичной пары требует каталога символов.
Проверки `SelectionCancellationTests` проходят вместе с проверками сравнения и Линейки.

Полный локальный набор запускается после сборки командой
`BotView.Tests.exe -trait- "Category=Integration"`. Тесты с реальными запросами
к биржам отмечены `Category=Integration`; для их отдельного запуска используется
`-trait "Category=Integration"`. Live-проверки стакана дополнительно требуют
`BOTVIEW_LIVE_ORDERBOOK=1`.
