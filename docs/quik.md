# Каталог, стакан и чтение счёта QUIK

BotView подключается к запущенному терминалу через **QUIKSharp 2.0.0** и показывает
инструменты классов TQBR (акции), TQOB (облигации), SPBFUT (фьючерсы).
Это список, доступный терминалу от брокера. Он не подтверждает индивидуальные права
счёта, достаточность средств или возможность сделки в текущую торговую сессию.
Для TQBR и SPBFUT доступны стакан Level II, чтение обычных и условных заявок,
исполнений, денежных остатков, гарантийного обеспечения и позиций выбранного счёта.
TQOB остаётся только в каталоге. Свечи и торговое исполнение не реализованы.
Все новые команды вызывают заглушки; существующие торговые кнопки QUIK отключены.

## Открытие стакана и счёта

1. Выберите **QUIK / Мосбиржа**, обновите каталог и нажмите ПКМ по TQBR/SPBFUT →
   **Стакан · только чтение**.
2. В **Trading accounts** создайте профиль **QUIK / Мосбиржа**, выберите
   `MoexShares` или `MoexFutures`, задайте адрес и порт терминала.
3. Нажмите **Загрузить счета и виды лимитов** и явно выберите фирму,
   торговый счёт, клиентский код и вид лимитов. При пустом портфеле варианты
   клиентского кода могут поступать из денежных лимитов; соответствующий
   торговый счёт выбирается пользователем. API-ключи не нужны.
4. Сохраните профиль и выберите его для подключения. Новые стаканы используют
   адрес выбранного QUIK-профиля; без выбранного профиля — `quik.json`.
5. Выберите профиль в стакане. **Orders** открывает обычные и условные заявки
   и исполнения. Отмена в этом окне отключена для QUIK.

Счета ограничены адресом подключения и рынком стакана. Сеть в криптовалютном
смысле не переключает терминал: учебный или боевой QUIK определяется самим
терминалом и его подключением к брокеру.

Каталог, стаканы и счёт используют общий владелец соединения с учётом потребителей.
Закрытие одного окна не останавливает остальные; подписка Level II снимается
после последнего потребителя этого инструмента. Данные стакана поступают через
`OnQuote`; каждые две секунды проверяются соединение и подписка. Метка времени
последнего события сохраняется без искусственного обновления. Запрос
`GetQuoteLevel2` не используется: Lua-комплект QUIKSharp 2.0.0 дублирует его ответ
в канал событий с ID запроса, нарушая проверку протокола в библиотеке и вызывая
`FailFast` через стандартный Trace listener приложения. После разрыва сохраняется
последний снимок с предупреждением, затем подписка восстанавливается.

События заявок сверяются со снимками; медленный ответ не перезаписывает более
новое событие. Фирма, счёт, клиент и торговый класс фильтруются отдельно.
Обычная и условная заявки имеют разные идентификаторы даже при совпадении номера.
Если фирму условных заявок нельзя определить однозначно, чтение показывает ошибку.

Объёмы акций отображаются в лотах, фьючерсов — в контрактах. Денежная оценка
использует размер лота либо стоимость шага и валюту расчёта. Отсутствующие метаданные
не заменяются вымышленными значениями; стоимость позиции не равна обеспечению.
Настройки и клавиши описаны в [BookCommands.md](BookCommands.md).

## Подготовка терминала

1. Установите QUIK из дистрибутива своего брокера и подключитесь к брокерскому серверу.
2. После сборки или публикации BotView найдите рядом с программой папку
   `Integrations/Quik`. Это Lua-комплект именно установленного NuGet-пакета,
   включая `clibs64/53_MD/socket/core.dll` для 64-битного QUIK с Lua 5.3.
3. Скопируйте **всю папку**, сохранив вложенные каталоги, в отдельное место,
   например `C:\QUIK\BotViewLua`. Не смешивайте её с файлами других коннекторов.
4. В QUIK откройте **Сервисы → Lua скрипты → Добавить**, выберите
   `C:\QUIK\BotViewLua\QuikSharp.lua`. Выберите интерпретатор **Lua 5.3** и запустите скрипт.
   Если терминал предлагает несколько версий Lua, важно выбрать 5.3: комплект пакета
   не содержит socket/core.dll для Lua 5.4. При ошибке загрузки socket/core.dll
   проверьте выбранный интерпретатор, разрядность QUIK и установленный Microsoft
   Visual C++ Redistributable x64.
5. Оставьте терминал подключённым, а скрипт — запущенным. В BotView выберите
   **QUIK / Мосбиржа**. Чтобы повторить загрузку, нажмите **Обновить**.

По умолчанию используется `127.0.0.1`: порт запросов **34130**, обратных вызовов
**34131**. Оба порта должны быть свободны для этого Lua-скрипта.
Наличие соединения с Lua-мостом и соединения самого QUIK с брокером проверяется отдельно.
Сам BotView не запускает QUIK, не устанавливает скрипты в терминал и не запрашивает
брокерские ключи или пароль.

## Нестандартное подключение

Создайте файл **quik.json рядом с BotView.exe**:

```json
{
  "Host": "127.0.0.1",
  "Port": 34130,
  "RequestTimeoutSeconds": 5
}
```

Если файла нет, используются эти же значения. `Port` — порт запросов; порт обратных
вызовов всегда равен `Port + 1`. В Lua-комплекте настройте соответствующую секцию
`QuikSharp` файла `config.json`: `responseHostname`, `responsePort`,
`callbackHostname`, `callbackPort`. После изменения настроек перезапустите BotView
и Lua-скрипт. Таймаут задаётся на один запрос, а не на получение всего каталога.

Lua-мост QUIKSharp не использует аутентификацию и шифрование. Оставляйте его
привязанным к локальному адресу; при удалённом подключении необходим защищённый
канал и ограничение сетевого доступа.

## Каталог и ошибки

- Фильтры **Все / Акции / Облигации / Фьючерсы** и поиск по тикеру или названию
  работают локально, не создавая дополнительных запросов в терминал.
- Неизвестные метаданные показываются как `—`. Отсутствующий класс даёт пустую
  категорию. Закрытие торговой сессии само по себе не удаляет инструменты из каталога.
- При обновлении каталог заменяется только после полной успешной загрузки.
  Если обновить его не удалось, предыдущий список остаётся с отметкой ошибки.
- Если QUIK не отвечает, проверьте работу скрипта, адрес и оба порта. Если QUIK
  не подключён к брокеру, выполните вход в терминале и повторите обновление.
- Переключение источника отменяет загрузку. Каталог не заменяется демонстрационными
  данными и не запускает загрузку свечей.

## Проверка с терминалом

Обычные тесты используют подменяемый клиент и не требуют QUIK. Отдельная проверка
реального подключения запускается явно после подготовки терминала:

```powershell
$env:BOTVIEW_LIVE_QUIK = '1'
& .\BotView.Tests\bin\Debug\net10.0-windows7.0\BotView.Tests.exe -class BotView.Tests.QuikInstrumentProviderTests -method '*LiveCatalog*'
```

Для проверки стаканов TQBR/SPBFUT, общего соединения и чтения доступных таблиц
счёта используйте отдельные проверки только на чтение. Они удерживают каждый
стакан не менее 15 секунд и проверяют отсутствие утверждений `Trace.Assert`:

```powershell
$env:BOTVIEW_LIVE_QUIK = '1'
dotnet BotView.Tests/bin/Debug/net10.0-windows7.0/BotView.Tests.dll -class BotView.Tests.QuikLiveReadTests -showLiveOutput
```

Они не вызывают размещение, изменение или отмену заявок и не сохраняют профили.
Маршрут счёта выбирается только в памяти для проверки каждого доступного рынка.
Вывод содержит количества записей без идентификаторов счёта и финансовых сумм.
Пустой список по выбранному инструменту подтверждает успешное чтение, но не
проверяет отображение непустых заявок/исполнений/позиций. Для этой проверки
не нужно создавать сделки или заявки специально.

Если переменная не установлена, этот тест пропускается. Для нестандартного адреса
положите `quik.json` также рядом с тестовым исполняемым файлом.
