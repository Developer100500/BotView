# Торговля из стакана

Торговый код разделён по обязанностям:

- `AbstractTradingService` — общая реализация `ITradingService`: вызовы CCXT, подготовка количества и цены, чтение и отмена заявок, баланс, приватные обновления, обработка ошибок и освобождение транспорта. За параметры конкретного рынка отвечают переопределяемые методы наследников.
- `SpotTradingService` — спотовая торговля криптовалютой через CCXT. Напрямую вызывает библиотеку и возвращает текущие модели приложения. Подключение торговли акциями будет добавлено отдельно.
- `FuturesTradingService` — отдельная торговля USDT-фьючерсами через CCXT с теми же моделями приложения. Выбор Spot/Futures внутри каждого торгового метода больше не требуется.
- `TradingServiceFactory` — создание нужного сервиса и CCXT.Pro-подключения Binance/Bybit, выбор Testnet/Mainnet до первого запроса.
- `ITradingService` — общий контракт стакана, который реализуют оба сервиса. Промежуточного торгового клиента с нативными результатами больше нет.
- `OrderInputCalculator` — пересчёт бюджета в количество, форматирование количества и цены через `ITradingService`, стоимость для превью с учётом размера контракта. Сессия предоставляет отдельный калькулятор для каждого подключённого инструмента.
- `TradingAccountSession` — снимок данных для UI, приватные подписки и резервный REST-опрос.
- `TradingSessionManager` — одна сессия на профиль для всех его окон, замена соединения при изменении ключей или профиля.

`SpotTradingService` и `FuturesTradingService` наследуют `AbstractTradingService`. В первом остаются параметры спотовой маршрутизации и Post-only, во втором — параметры позиции, контрактные единицы, запрос позиций и публичный каталог USDT-контрактов. `TradingServiceFactory.Create` возвращает `ITradingService`; сессия стакана не зависит от конкретного наследника.

`QuikReadOnlyTradingService` реализует `ITradingService` для чтения TQBR/SPBFUT,
явно возвращает `CanExecuteTrades = false` и отклоняет все методы мутации до доступа
к транспорту. `TradingServiceFactory.Create` возвращает `ITradingService`, сохраняя
CCXT-наследование внутри криптовалютных адаптеров. Профилям QUIK ключи не требуются.
Каталог, счёт и стакан используют общий владелец соединения QUIK.

Новые горячие клавиши используют отдельный `ICommandInvocationHandler` и
`StubCommandInvocationHandler`, которые не зависят от `ITradingService` и не
вызывают существующий торговый код. См. [BookCommands.md](BookCommands.md).

## Заявки

По умолчанию выбран Limit. Он принимает цену и количество монет/контрактов либо бюджет в валюте котировки. Бюджет пересчитывается по форматированной цене с учётом размера контракта. Превью показывает подготовленные количество, цену и стоимость без комиссии. Post-only доступен только для Limit.

Market принимает только количество монет или контрактов. Поле цены, бюджет в USDT и Post-only отключены. При переключении типа количество очищается, чтобы бюджет случайно не стал количеством монет. Точная цена и стоимость Market не обещаются.

Оба сервиса предоставляют `CreateLimitOrderAsync` и `CreateMarketOrderAsync`, принимая соответственно `LimitOrderRequest` и `MarketOrderRequest`. Рынок определяется классом сервиса: спотовые методы не получают фьючерсные параметры, а фьючерсные методы формируют параметры позиции непосредственно перед вызовом CCXT. Создание сервиса с профилем другого рынка отклоняется.

Проверяются обязательные поля, положительные числа, направление и преобразование точности средствами CCXT. Баланс, комиссии, маржу, лимиты и режим позиций проверяет биржа. Ошибки показываются в форме без ключей, подписанных URL и исходных тел запросов.

Один клик отправляет один запрос. На время запроса форма блокируется. Тайм-аут означает неизвестный результат и не вызывает автоматическую повторную отправку. Перед повторным действием следует проверить заявки на бирже.

## Данные и подписки

Начальная загрузка получает инструмент, баланс, открытые заявки и последние исполнения. Приватные `WatchOrders`, `WatchMyTrades`, `WatchBalance` обновляют снимок интерфейса. Для фьючерсов позиции опрашиваются REST раз в две секунды.

Если поток не поддерживается или завершился ошибкой, REST раз в две секунды обновляет только соответствующие данные. После восстановления потока загружается свежий снимок, резервный опрос прекращается. Медленный REST-ответ не заменяет более новые приватные события. Заявки объединяются по инструменту и биржевому ID, исполнения — также по ID исполнения. Это текущие данные UI, а не долговременная история.

После успешного создания/отмены обновляются данные аккаунта. Ошибка чтения не превращает успешную отправку в отказ. Массовая отмена подтверждает зафиксированный список ID и показывает индивидуальный результат каждой отмены.

## Жизненный цикл

Журнал намерений, фазы операций, локальные резервы и восстановление отправок удалены. Старый `trading-journal.db` не читается и не удаляется. Формат профилей сохранён; ключи остаются только в памяти.

Закрытие стакана оставляет общую сессию приложения работающей. Смена ключей/профиля закрывает старое соединение; завершение приложения освобождает транспорт. Эти действия не отменяют биржевые заявки.

## Автономные проверки

Сборка: `dotnet build BotView.Tests/BotView.Tests.csproj --no-restore`.

Тесты: `dotnet run --project BotView.Tests/BotView.Tests.csproj --no-build -- -class BotView.Tests.TradingServiceTests -class BotView.Tests.TradingAccountSessionTests -class BotView.Tests.BinanceRequestParametersTests -class BotView.Tests.FuturesTradingTests`.

Тесты используют вымышленные ключи и подменённые транспорты. Реальные заявки не отправляются.

## Плечо фьючерсов

В фьючерсном стакане поле `Leverage (x)` позволяет выбрать готовое значение или ввести целое число от 1. Кнопка `Apply leverage` отправляет один вызов CCXT `SetLeverage` для текущего инструмента. Максимум и доступность изменения проверяет биржа. На Bybit одно значение применяется к Long и Short. Смена плеча не меняет количество заявки и не отправляет заявку.

Поле очищается при подключении аккаунта; само подключение не меняет плечо на бирже. Текущее плечо позиций отображается в строке позиций, введённое значение становится подтверждённым только после успешного ответа на применение. Во время запроса форма блокируется; ошибки и тайм-ауты показываются без автоматического повтора. Для Spot поле скрыто.

Под плечом показывается оценка начальной маржи: подготовленное количество × размер контракта × цена / выбранное плечо. Для Limit используется подготовленная цена, для Market — отдельные оценки Buy/Sell по лучшим ask/bid свежего стакана. При устаревшем или отключённом потоке Market-оценка недоступна. Расчёт не включает комиссии, проскальзывание и биржевые корректировки; он не является расчётом поддерживающей маржи и не блокирует отправку заявки. Выбранное плечо нужно отдельно применить на бирже. Для Reduce-only оценка открытия позиции не применяется.

Фьючерсные заявки всегда указывают сторону Long или Short (по умолчанию Long). Вариант Auto удалён; запрос без стороны отклоняется до отправки. Аккаунт на бирже должен использовать hedge/two-way mode.
