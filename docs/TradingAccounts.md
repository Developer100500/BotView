# Торговые счета

Кнопка **Торговые счета** в MainWindow открывает управление профилями Binance и Bybit.
Поддерживаются спотовые счета с HMAC API key/secret, Testnet и основная сеть.
Bybit Demo и подключение счетов QUIK в эту версию не входят.

1. Нажмите **Добавить счет**, задайте название, биржу и среду. По умолчанию выбран Testnet.
2. Введите API key и API secret в маскированные поля и нажмите **Сохранить**.
3. **Проверить подключение** читает данные счета и доступные сведения о правах API.
   Эта проверка не выставляет заявки и не отправляет запросов на вывод.
4. **Выбрать для биржи** сохраняет профиль и сеть для вновь открываемых стаканов.
   Для каждой биржи выбирается один активный профиль. Buy/Sell поддерживают спотовые
   Limit GTC и Post-only для Binance/Bybit.

Ключи сохраняются в **Windows Credential Manager** для текущего пользователя Windows
на этом компьютере и доступны после перезапуска приложения и повторного входа в Windows.
API key и API secret находятся вместе в защищенном blob одной Generic Credential;
имя записи — `BotView/TradingAccounts/{ID профиля без дефисов}`. Название, биржа, среда
и выбор счета сохраняются отдельно в `%LOCALAPPDATA%/BotView/trading-accounts.json`,
без ключей и результатов проверки. Проверка подключения после запуска выполняется вручную.
Ключи из прежней версии, хранившиеся только в памяти завершенного процесса, нужно ввести один раз заново.

Сохраненные ключи не подставляются в форму. Для замены нажмите **Заменить ключи**, введите оба новых значения
и сохраните; для переименования достаточно изменить название. Чтобы изменить рынок
существующего профиля, выберите **Market** (Spot или UsdtFutures) и нажмите **Save**.
Среду также можно изменить в поле **Environment** (Testnet или Mainnet) и сохранить через **Save**.
Ключи остаются в хранилище; после смены рынка или среды проверку подключения нужно выполнить заново.
При необходимости замените ключи на подходящие для новой среды.
Биржа существующего профиля неизменяема: создайте другой профиль для другой биржи.
**Удалить** удаляет профиль и его запись в Credential Manager, но не отзывает API-ключ на бирже.

Хранилище используется через `ICredentialStore`. Реализация `WindowsCredentialStore`
подключена в `App.TradingCredentials`; для замены провайдера достаточно изменить эту
точку создания. Окна, модели представления и торговые сессии не обращаются к Windows API.
`Read` возвращает отдельную копию `AccountCredentials`, которую вызывающая сторона
освобождает через `Dispose`. Само закрытие хранилища не удаляет сохраненные ключи.
Для уведомления торговых сессий о замене или удалении ключей провайдер реализует
`ICredentialNotifications`. `InMemoryCredentialStore` остается доступным для тестов
и сценариев без постоянного хранения. Временные байтовые буферы реализации Windows
очищаются после чтения и записи. Общий размер записи с заголовком ограничен 2560 байтами.
Лимит и режим хранения описаны в [документации Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/wincred/ns-wincred-credentialw).

Доступ к чтению счета и торговые разрешения проверяются отдельно. В Binance Spot
Testnet нет `/sapi`, поэтому подключение может быть подтверждено при неизвестных правах.
Если сведения о правах недоступны, интерфейс показывает неизвестное состояние;
явный запрет блокирует отправку, окончательное решение принимает биржа.
Для торговли достаточно чтения и спотовой торговли без права вывода.

Проверка выполняется в фоне отдельным авторизованным CCXT-клиентом с общим тайм-аутом
15 секунд. Смена выбранного профиля, кнопка отмены и закрытие окна отменяют проверку.
Основная сеть не используется как запасной адрес для Testnet. Клиенты публичного
стакана, графика и QUIK не получают ключей и продолжают работать независимо.
Результаты и ошибки не содержат исходные ответы API, подписанные URL или секреты.

Автоматические проверки используют вымышленные ключи и подставные ответы бирж.
`WindowsCredentialStoreTests` обращается к реальному Windows Credential Manager,
создает записи со случайными ID и удаляет их в `finally`:

```powershell
dotnet build BotView.sln --no-restore -m:1 -p:UseSharedCompilation=false
dotnet BotView.Tests/bin/Debug/net10.0-windows7.0/BotView.Tests.dll -class BotView.Tests.TradingAccountTests
dotnet BotView.Tests/bin/Debug/net10.0-windows7.0/BotView.Tests.dll -class BotView.Tests.WindowsCredentialStoreTests
```

Для ручной проверки реального Testnet-подключения введите соответствующие ключи
непосредственно в окно приложения и нажмите **Проверить подключение**.
